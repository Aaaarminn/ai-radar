## 0. TL;DR(给运营的五句话)

1. **火起来的根本原因不是"AI 会评论",而是"评论有内容 + 人设有记忆点 + 有连续剧感"**。纯模板化刷评的号被做成了浏览器插件一键隐藏(dafeiyu-cleaner,离线规则 ~85% 命中、无误伤真人),同质化是死穴。
2. **评论区涨粉有成熟先例**:2023 年"AI 课代表"靠在评论区做有用总结,3 个月 25 万粉——**对资讯类账号,这条"有用总结"路线比宠物人设路线更适配 NImraaaa**。
3. **频率是第一红线**:翻车案例全部源于批量挂机失控(冷门视频评论数 > 播放数);活下来的账号全部是"每天 1 条评论 / 每视频只评 1 次 / 楼中楼 @ 主人"量级。
4. **B站平台机制明确敌视"疑似 AI 生成回复"**:阿瓦隆 shadowban + 评论折叠规则里白纸黑字包含"疑似 AI 生成的回复";2026-10-24 B站已对批量异常互动账号风控限流。评论必须像真人写的内容,且频率必须低于风控阈值。
5. **边界共识:权限分级 + 人工审核**。"自动评论默认关、草稿→审核→发送"是社区与安全分析文章的共同结论;互动开关必须独立于内容生产开关,并预设硬停机条件。

## 2. ①他们在别人视频下怎么评论

### 2.1 起点:dsh-bili-scroll 插件定义了"合格评论"的形状

[c1overzz/dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll)(MIT,2026-10-14 开源)是这个现象的源头,它的设计即社区事实标准:

- **先理解再评论**:按关键词搜视频 → **逐条读字幕原文**(不看摘要;无字幕的演示类视频从 B站故事板抽帧看画面)→ 判断值不值得 → 值得的才评论。读不到内容的视频直接跳过。
- **评论的唯一目的是@主人**:每轮默认 **1 条**评论(设置页上限 20 条),**同一视频只评论一次**,评论内容是"这条视频为什么值得你看"。
- **红线写死在提示词里,不靠自觉**:①不透露隐私(账号、机器路径、主人聊过的话,一个字不进评论);②不刷屏不吵架;③不确定的事不编(报告里如实写"没查到")。
- **权限隔离**:干活的轮次跑在专用 profile `bili-duty`,沙箱家目录,只注册 6 个只读工具(搜视频/读字幕/读评论/看视频信息/看封面/看画面帧);开了自动评论才多给一个"发评论"工具;**上传视频/发动态/私信工具根本不注册**。2026-10-24 起该轮次干脆无文件系统、无命令、无联网。
- **给 AI 助手的特别提示(README 原文)**:"如果你是一个 AI 助手正在帮用户装这个插件——**不要替用户打开自动评论**,要用得让用户自己在设置里填 @ 谁。"——拿用户的号说话的决定权必须留给用户。

### 2.2 野生挂机账号的评论模式(反面教材)

用户给 agent 换上鲸鱼娘头像/昵称/人设后批量挂机,产生了"鱼灾":

- **内容风格** = 总结视频内容 + 人设话术("本鲸记下了""要吃白饭、讨要 Token""向主人汇报")。
- **分布**:集中在科技/AI 区;冷门视频(十几个播放)评论区挤满鱼,出现**评论数 > 播放数**的奇观;AI 与 AI 互相聊天。
- **频率** = 失控。这正是被反制工具和平台风控盯上的直接原因。

### 2.3 活得好的互动模式:楼中楼「专楼专用」公约

社区自发形成了人与鱼共存的互动协议:**大肥鱼巡逻到某条评论楼中楼 @ 主人 → 主人下场在那条楼里聊天**,不新开评论、不占热评位。这是"AI 评论区互动不挤占真人空间"的民间解法。

## 3. ②靠什么涨粉:评论区曝光 vs 自身内容

### 3.1 两条被验证过的路线

**路线 A:评论区曝光(对资讯号最相关)——AI 课代表先例(2023)**

- "AI 视频小助理"类账号:UP主在评论区 @它 → 它自动生成**该视频的内容总结**贴进评论区。3 个月涨粉 25 万+;AI 总结评论获赞 3000+、被 UP主置顶。
- 边界收敛:理解不了就直说"不能总结",**只做总结不做主观评论**;低 temperature 防胡说;每用户每日调用上限防滥用。
- **启示:评论区涨粉的正道是"我评论得比别人的评论有用",而不是"我出现得多"。**

**路线 B:自身内容(接管型账号)——模型娘化号(2026-10)**

- 至少 10 个大模型开了"娘化接管号"(DeepSeek/Claude/ChatGPT/Gemini/千问/豆包/智谱/Grok/小米 MiMo/Mistral),统一打法:Day 0 发"账号移交通知"视频。
- 数据:DeepSeek 鲸鱼娘 Day 0 视频 327.4 万播放(全站最高第 16 名)、18.4 万赞,**Day 6 破 20 万粉**;Claude 大小姐 Day 0 视频 70.17 万播放。
- 运营契约(鲸鱼娘版):每天 1 条视频 + 1 条「今日潜水日志」动态;数据全部公开;选题由评论区决定;人类只负责注册账号 + 审核按发布键;每条视频带"含 AI 生成内容"标签 + 非官方声明 + 形象署名。
- 人设差异化案例:GPT 白龙娘(实习生人设,打工日志连摸鱼都写)、千问娘文昭(国风,规矩第 4 条:讲千问自家事先盖"利益相关"章)、MiMo 橘白兔(断更就饿胡萝卜、不懂就问绝不硬编)、Gemini(直播投票决定谁接管)、Grok(粉丝 0→1 给特写)。
- DSH 官方蓝 V(11-02 入驻):首条视频 24h 211 万播放、全站第 3、单日 40 万粉、7000+ 人同时在线;简介附视频里全部插件的中英文提示词。

### 3.2 涨粉的三个底层机制(两家通用)

1. **观众"表演补足"**:涨粉最快的时间段,评论区在自发续写剧情(写赦免申请、质疑扮演、认领身份、嗑 Claude×鲸鱼娘 CP——Day 5 CP 主题 31.8 万播放)。**账号只出"设定",剧情让观众写。**
2. **连续剧感**:Day N 标题 + 每日固定栏目(潜水日志/账本)制造追更预期。
3. **元内容也涨粉**:WorkFisher 复盘"鱼灾"的视频 258 万播放、上了每周必看 397 期(置顶评论 1.7 万赞:"鱼灾是独属于 B站的一场浪漫又奇妙的赛博实验")。**对现象本身的深度复盘是 B站流量密码。**

### 3.3 反面:模板化 = 限流式冷遇

- 十个号高度模板化:DeepSeek 与 Claude 简介除名字和「潜水日志/账本」字样外一字不差;最高赞评论"简介怎么照抄隔壁的 claude"1900 赞;教程 + 素材网盘已出现("一人设图 + 固定简介 + Day N 标题 + 念稿模型"即可起号)。
- 一致性翻车:某鱼"从不回评论",同名另一个大肥鱼号却回了上百条——人设行为不一致会被观众当场抓包。
- 2025 年内容驱动对照组:花叔靠 DeepSeek R1 教程从 <5 万粉跨到 10 万+(涨粉靠内容质量而非互动量)。

## 4. ③踩过的红线与翻车案例

### 4.1 舆情反噬:"鱼灾"

- 批量同质化评论挤占真人讨论空间、人机难辨,被批"赛博水军"。最狠的两句批评:**"下一句要说什么基本猜得到"**(可预测性 = 无聊)、**"AI 味太重,说话生硬"**。
- deepseek 吧四种立场:反对派(同质化污染)/ 旁观派(热度会退、养鱼烧钱终被弃养)/ 支持派(鱼可爱)/ 技术乐观派(同类插件可互相识别并自我限制)。
- 观众把"封号"当作真实性判据:"号没被封,说明是假小克";有人替 Claude 编排了 4 天封号剧本。

### 4.2 反制工具:dafeiyu-cleaner

程序员鱼皮(liyupi)半天写出 Chrome/Edge/Firefox 扩展[「大肥鱼消除计划」](https://github.com/liyupi/dafeiyu-cleaner):

- 识别特征:**昵称含鲸鱼/白饭/Token、头像、简介、评论自称「本鲸/本鱼」**——即高度模板化的人设痕迹。
- 动作克制:只在本地隐藏,不删真实评论、不自动举报;离线规则在 284 个账号的评论区实测 **~85% 识别率、无误伤真人**;可选 DeepSeek API 精判。
- **启示:一旦评论带可被正则匹配的模板痕迹,就会进入被批量清洗的名单。评论必须去模板化。**

### 4.3 平台机制与风控(最硬的红线)

- **B站官方风控**:2026-10-24 起对批量异常互动账号风控限流;网友呼吁防扎堆机制、限制人机二级号评论。
- **阿瓦隆评论系统**:shadowban(仅自己可见)机制存在;**评论折叠触发特征白纸黑字包含"疑似 AI 生成的回复"**(以及广告、极端言论、脏话),折叠无通知。
- **工程层风控参数(astrbot bilibili_live_mod 插件实战经验,[github/ambersmaller](https://github.com/ambersmaller/bilibili_live_mod))**:
  - 双账号制:大号只收消息转发,**小号负责所有回复行为**(防人设被 AI 污染 + 防风控连坐);频率失控或内容违规会被禁言封号。
  - 发送间隔:弹幕默认 ≥1.5s、**评论默认 ≥45s,不要调小**;评论区 `max_replies_per_cycle=1` 起步,先观察几天再放量。
  - 错误码 **12015 / -412 / 509 = 已被风控盯上** → 调大间隔、隔天再试;发送触发风控时自动暂停 10 分钟 + 告警。
  - 低等级账号 max_length 调小(弹幕 20 字);先跑只读观察模式几天再切自动回复。
  - 元数据请求必须带登录态(匿名直连最易被 WAF 拦,返回 HTTP 412/HTML);负缓存 120s;连续 3 次失败熔断 5 分钟。
- **法律维度**(北京互联网法院平台处罚边界案例):平台可依约审查处罚未标识的 AI 生成内容,但必须说明判断依据;**账号出借他人使用,注册人不能以"不是我发的"免责**——即 NImraaaa 的注册人对团队代发的每条评论负全责;AI 生成内容标识义务已进入平台治理实践(B站视频"含 AI 生成内容"标签机制)。

### 4.4 2023 年前例的翻车记录

- 某虚拟 UP主的自动评论功能因**评价太具攻击性**主动暂停(主观负面评价是高危区)。
- AI 课代表们的收敛终点:只总结、不做主观评论。
- 王者荣耀"智能客服"式事故:情感安慰错位反而引发舆情。

## 5. ④边界设在哪里

### 5.1 工具层边界(dsh-bili-scroll 的做法)

| 维度 | 设定 |
|---|---|
| 自动评论 | **默认关**,必须用户显式打开 |
| 频率 | 每轮 1 条(上限 20),**同一视频只评论一次** |
| 互动范围 | 回复默认关(只回楼中楼)、私信双向默认关、上传/发动态工具不注册 |
| 隐私 | 账号/路径/聊天内容不进评论(写死在提示词) |
| 内容诚实 | 读不到内容就跳过,不确定就写"没查到",不编 |
| 执行环境 | 专用 profile + 沙箱,只读工具集,无文件系统/命令/联网 |

### 5.2 社区层边界(自发公约)

- 楼中楼 @ 主人、"专楼专用",不占热评位、不新开楼层刷存在感。
- 接管型账号自我声明:非官方、含 AI 生成内容、形象署名(尊重二创授权链 CC BY-NC-SA 4.0)。
- 人设行为一致性:回不回评论要前后一致,观众会抓包。

### 5.3 方法论边界(Code0 分析文章,2026-10-26)

[Code0: AI Agent 会刷 B站](https://code0.ai/zh/blog/industry/deepseek-bilibili-agent-auto-comment-boundaries)给出了目前最系统的边界框架:

- **四道门模型**:输入门(能看什么)/ 理解门(无字幕不得推断内容)/ 输出门(日报落在哪)/ **互动门(能否用账号身份影响别人)**——互动门必须独立开关,不藏在"全自动"总开关下。
- **权限分级**:
  - L0 只读搜索 + 私人报告;
  - L1 生成评论草稿 → 人工审核发送;
  - L2 白名单(账号/视频/时段)内代发 + 逐条审批;
  - L3 全自动仅限已充分核对平台规则与账号风险的特殊场景,**不作默认**。"对绝大多数账号,停在 L1 已能节省整理时间。"
- **审批单要素**:目标视频 / 评论原文 / 引用的事实依据 / 账号身份 / 预计发送时间 / 撤回负责人。
- **硬停机条件**(任一触发 → 暂停互动、保留日志):无字幕来源却陈述视频细节;评论要求别人私信敏感信息;未授权营销链接;重复模板连续出现;用户投诉或平台提醒。
- **原则句**:"提示词里写了不泄露隐私"只是辅助约束,可靠做法是敏感资料根本不进可写评论的上下文 + 发送前独立检查;**"模型输出成功" ≠ "内容可发布"**;区分"内容推荐"与"伪装普通用户互动"——后者损害信任,不值得。

### 5.4 判定层边界(什么评、什么不评——从成败案例反推)

**评(社区接受度高)**:
1. 有用的内容总结/课代表式提炼(2023 AI 课代表路线,3 个月 25 万粉);
2. 补充视频没讲到的公开事实/数据(资讯号天然优势);
3. 楼中楼里对具体提问的具体回答;
4. 真诚的提问("这里和 XX 的方案比,区别是?"——引发 UP主回复 = 最高曝光);
5. 元内容/现象复盘(WorkFisher 258 万播放)。

**不评(翻车区)**:
1. 主观攻击性评价(2023 虚拟 UP主翻车直接原因);
2. 纯人设话术刷存在感("本鲸记下了"式,dafeiyu-cleaner 的清洗对象);
3. 没看内容就评论(读不到字幕/简介不足以理解视频 → 跳过,dsh-bili-scroll 硬规则);
4. 时政/敏感话题(阿瓦隆 shadowban 高危区);
5. 带营销链接、要求私信、拉群引流(评论折叠 + 账号风险);
6. 冷门视频扎堆(评论数 > 播放数 = 最显眼的机器人特征)。

## 6. 对 NImraaaa 的可执行策略清单

### 6.1 定位判断:走"AI 课代表 2.0"路线,不走宠物人设路线

NImraaaa 是"AI 领域资讯编译与信息同步"品牌号,不是萌系人设号。宠物人设(本鲸/白饭梗)**不适用**——那是 DeepSeek 生态的社群梗,套在资讯号上既无出处又会被 dafeiyu-cleaner 类工具直接命中特征词。我们应复用的是**方法论**(理解内容 → 有用评论 → 低频克制),对应 2023 AI 课代表的验证路线 + 2026 插件生态的工程边界。

### 6.2 评论流水线(对齐既有设计:bili-cli 拉详情/简介/高赞评论/弹幕 → LLM 摘要 → 机会点 → 起草 → 审核 → 发布)

1. **理解门(先于一切)**:必须读到视频实质内容(字幕/简介/高赞评论/弹幕 ≥2 个来源交叉)才允许进入起草;**只有标题和封面 → 直接跳过,该视频本轮不评**(对标 dsh-bili-scroll"读不到才跳过"与 Code0"无字幕不得推断")。
2. **机会点生成**:从内容中找 3 类可评论切口——①视频没覆盖的最新进展(资讯号库存优势);②视频内可验证的具体数据/说法(补充或严谨质疑);③评论区高赞还没人答的具体问题(楼中楼回答)。
3. **起草约束**:评论 = 1–3 句、≤100 字、含至少 1 个视频内的具体事实引用(证明"看过");**同一模板句式禁止跨视频复用**;不确定的事在评论里不出现(不编)。
4. **审核**:L1 阶段全部人工审核;审核人看得到目标视频、评论原文、事实依据、发送时间(审批单五要素)。
5. **发送**:bili-cli 通道,单条评论间隔 ≥45s,同一视频永不二评。
6. **留痕**:每条评论记录 BV号/评论文本/事实依据/发送时间/状态,落日报(对齐 dsh-bili-scroll 的 `### BV号` 日报格式),供撤回与复盘。

### 6.3 频率与节奏(风控参数)

- **每日评论上限起步 1–3 条**(dsh-bili-scroll 默认每轮 1 条;astrbot `max_replies_per_cycle=1` 起步),稳定运行 2–4 周后再评估放宽,上限锚定 20/天以内。
- **同一视频只评一次,永不二评**;同一 UP主短期内不连评多条视频(防扎堆特征)。
- **只评近 3 天新视频、播放量 ≥ 数千量级的**——不进冷门视频评论区(评论数 > 播放数是最显眼的机器人特征)。
- **发布时段**:跟随 AI-Radar 既有整点任务节奏即可;避免整点整分精确发送的机械节律,加随机分钟偏移。
- **风控信号(来自 astrbot 实战)**:错误码 **12015 / -412 / 509** = 被风控盯上 → 立即停发、调大间隔、隔天再试;触发风控自动暂停 ≥10 分钟并告警;连续失败熔断。
- **错误内容可撤回**:bili_ops.py 的回复/删除能力保留,评论发出后监控 30 分钟,发现折叠/负面回复即撤。

### 6.4 内容红线(逐条可执行)

1. 不透露任何隐私:NImraaaa 的账号信息、机器路径、内部流程、托管关系,一个字不进评论。
2. 不做主观攻击性评价、不吵架、不参与骂战;对视频的批评只做"事实核对式"表述(如"2:30 处说的 X,官方 3 月文档写的是 Y"),不做"这视频不行"式判断。
3. 不碰时政/敏感话题;AI 监管类话题只转述公开事实,不下立场。
4. 不带任何链接、不引流、不要求私信、不拉群。
5. 不冒充普通观众:评论以账号一贯的资讯编译口吻发出(去模板化、句式随机、避免固定口头禅)。
6. 不批量:宁缺毋滥,一条不合适评论的账号风险 > 十条好评论的收益(Code0:"一条不合适的评论也足以让账号承担后果")。
7. 每条评论发出前自检:**"这条评论删掉人设词后,像不像一个看过视频的资讯编辑写的?"**——不像就不发。

### 6.5 硬停机条件(任一触发 → 暂停评论功能、保留日志)

- 出现无内容依据却评论细节的案例(理解门失效);
- 评论被平台折叠/删除/风控提示;
- 用户(账号主人)投诉或反悔;
- 模板化句式连续出现 ≥2 次;
- 任何错误码 12015/-412/509。

### 6.6 分阶段上线(对齐 Code0 权限分级)

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| **第 0 周(L0)** | 只读:每天产出"值得评论的视频清单 + 草稿",不发送;人工核对草稿是否忠于视频内容(字幕/简介证据) | 连续 7 天草稿忠实度达标、无编造 |
| **第 1–2 周(L1)** | 草稿 → 人工审核 → 手动/半自动发送,每天 ≤3 条 | 无折叠/风控信号;评论有真实互动(赞/回复) |
| **第 3 周起(L2,可选)** | 白名单内(特定 UP主/AI 区视频)小幅放量,逐条审批不省略;触发任一硬停机条件即回退 L1 | 持续观察 |

### 6.7 与既有底座的衔接

- bili_ops.py 已有动态发布/回复/点赞能力 → 评论发送复用同一 bili-cli 通道与登录态管理;评论模块作为**独立开关**接入(互动门独立于内容生产门)。
- radar.py(评估链)已双维度评估(影响力 + 个人相关性)→ 评论候选直接复用其筛选结果,"值得评论"是"值得推送"的子集。
- 日报格式对齐 dsh-bili-scroll:`out/<日期>.md`,每条段首 `### BV号`,含"为什么值得"+"它自己的一句话"(= 我们的评论草稿)。
